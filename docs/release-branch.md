# Release branch workflow

## Назначение

Релизная ветка используется для подготовки конкретного выпуска (например, `v1.0.0`): в ней выполняются только стабилизация и релизные исправления.

## Нейминг

- Формат ветки: `release/X.Y.Z` (пример: `release/1.0.0`)
- Формат тега: `vX.Y.Z` (пример: `v1.0.0`)

## Порядок работы

1. Выбрать базовую стабильную ветку (обычно `main`).
2. Создать релизную ветку:
   - `git checkout main`
   - `git pull`
   - `git checkout -b release/1.0.0`
3. Вносить только релизные правки (без новых крупных фич).
4. Прогнать финальные проверки и тесты.
5. Поставить тег:
   - `git tag v1.0.0`
6. Слить `release/1.0.0` в `main` (и при необходимости в `develop`), затем удалить релизную ветку.
